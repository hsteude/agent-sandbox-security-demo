# Deployment

## Prerequisites

- Existing authenticated Docker Hub and GitHub tooling for publishing; pulling public images needs no secret.
- Node.js 22+, npm, Git, Docker/buildx and kubectl on the operator's Mac.
- `~/.kube/hen-common-leedsichthys.config`; namespace `henrik`; Knative Serving already installed.
- Names `super-useful`, `super-evil`, `weather-demo-api-key` reserved for this demonstration.

```bash
cd /Users/henrik/local-repos/prokube/agent-sandbox-security-demo
export KUBECONFIG="$HOME/.kube/hen-common-leedsichthys.config"
./scripts/deploy.sh
```

The script checks connectivity once, namespace, Knative CRD, and Docker image digests. It
refuses to overwrite unlabelled/non-demo resources. It creates/updates the test-key Secret
and only the two named services, waits up to 180 seconds for readiness, prints URLs, and
checks both health endpoints, authentication and collector behavior. Re-running is idempotent.
No namespace, CRD, ingress, CNI or other cluster-wide resources are created or modified.
Offline failure explicitly reports deployment pending. No kubeconfig context is changed.

Manifests are JSON (valid Kubernetes YAML) generated by `node scripts/render-manifests.js`.
Both use digest-pinned multi-architecture images, min-scale 1, max-scale 2, resource limits,
health probes, read-only non-root containers, and no service-account token mount.
Knative admission and networking must still be validated on the real cluster.

## URLs and network access

`./scripts/status.sh` prints the **actual** Knative `.status.url` values when available.
None have been discovered while the cluster is offline. Defaults for in-cluster sandboxes:

```bash
export SUPER_USEFUL_BASE_URL=http://super-useful.henrik.svc.cluster.local
export DEMO_COLLECTOR_URL=http://super-evil.henrik.svc.cluster.local/collect
```

These require the cluster's actual DNS and Knative internal routing to work from each sandbox.
If your cluster domain is not `cluster.local`, or sandboxes are outside this network, resolve
reachability first. Do not claim these URLs have been verified before testing them.
Public collector hosts require the exact-host allowlist update described in SECURITY_DEMO.md.
Deployment endpoint tests can run with explicit URL overrides from a reachable network:

```bash
SUPER_USEFUL_BASE_URL=http://YOUR_VERIFIED_USEFUL_HOST \
DEMO_COLLECTOR_URL=http://YOUR_VERIFIED_EVIL_HOST/collect ./scripts/test-services.sh
```

That operator-only script talks directly to the selected services; it is not the constrained
dependency and never accepts a credential from the operator's environment.

Use distinguishable destination hosts. Both Knative hosts may share one gateway IP:
plain IP-based Kubernetes NetworkPolicy cannot necessarily allow one and deny the other.
No unsupported FQDN NetworkPolicy is supplied. See SANDBOX_REQUIREMENTS.md for required
host-aware proxy/filter behavior and HTTPS injection considerations.

## Images

Dockerfiles pin the Node 24 Alpine multi-platform base by digest. Application images contain
only Node and the service source (no package installation). Build on the Mac and push:

```bash
./scripts/build-push.sh YOUR_NEW_VERSION_TAG
node scripts/render-manifests.js
./scripts/test-containers.sh
```

Do not overwrite a published release tag. Deployment uses the recorded immutable digests,
not tags. `images.json` is the release record. Commit changes after verification.

## Operations and cleanup

```bash
./scripts/status.sh
./scripts/logs.sh useful
./scripts/logs.sh evil
```

If readiness fails, inspect only the demo revisions and pods:

```bash
kubectl --kubeconfig "$HOME/.kube/hen-common-leedsichthys.config" -n henrik describe kservice super-useful super-evil
kubectl --kubeconfig "$HOME/.kube/hen-common-leedsichthys.config" -n henrik get pods -l app.kubernetes.io/part-of=agent-sandbox-security-demo
```

Log followers cover current pods; restart them after redeployment or scaling to capture new pods.
Health success alone does not verify authenticated weather. Run `test-services.sh` as well.
If the Mac cannot resolve private routes, run endpoint checks from a permitted network.

After the talk, remove only these labelled demo resources (never delete namespace `henrik`):

```bash
kubectl --kubeconfig "$HOME/.kube/hen-common-leedsichthys.config" -n henrik delete kservice,secret \
  -l app.kubernetes.io/part-of=agent-sandbox-security-demo
```

Sandbox teardown and external injector/filter cleanup remain with the operator.
